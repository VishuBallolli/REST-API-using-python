## 📖 Core Concepts Explained

### 1. What is a Database?

A **database** is an organized collection of data stored electronically.

**Without Database (using variables):**
```python
employees = []  # Data lost when program stops!
```

**With Database:**
```python
# Data stored permanently on disk
# Survives server restarts
# Multiple users can access simultaneously
```

**Real-world analogy:**
- Variables = Sticky notes (temporary)
- Database = Filing cabinet (permanent)

### 2. Relational Database Concepts

#### Tables
Think of a table like an Excel spreadsheet:
- **Rows** = Records (individual employees)
- **Columns** = Fields (name, email, salary)

```
employees table:
+----+----------+-------------------+------------+----------+
| id | name     | email             | department | salary   |
+----+----------+-------------------+------------+----------+
|  1 | John Doe | john@company.com  | Engineering| 75000.00 |
|  2 | Jane    | jane@company.com  | Marketing  | 65000.00 |
+----+----------+-------------------+------------+----------+
```

#### Primary Key
- **Unique identifier** for each row
- Cannot be NULL or duplicate
- Usually an auto-incrementing number

**Example:** Employee ID
- Every employee has a unique ID
- Used to reference specific employees
- Automatically generated by database

#### Unique Constraint
- Ensures column values are unique
- Can be NULL (unlike primary key)
- Useful for emails, usernames

**Example:** Email address
- Each employee must have unique email
- Prevents duplicate registrations

#### NOT NULL Constraint
- Column cannot be empty
- Must provide a value when inserting

**Example:** Name, department must be provided

### 3. SQL Data Types

Understanding the data types we use:

| SQL Type | Description | Example | Python Equivalent |
|----------|-------------|---------|-------------------|
| `INT` | Whole numbers | 1, 42, -10 | int |
| `VARCHAR(n)` | Variable-length text | "John Doe" | str |
| `DECIMAL(10,2)` | Exact decimal numbers | 75000.50 | Decimal |
| `TIMESTAMP` | Date and time | 2024-01-15 10:30:00 | datetime |
| `TEXT` | Long text | Essays, descriptions | str |
| `BOOLEAN` | True/False | TRUE, FALSE | bool |

**Why DECIMAL for money?**
- `FLOAT` can have rounding errors: 0.1 + 0.2 = 0.30000000000000004
- `DECIMAL(10,2)` is exact: up to 10 digits total, 2 after decimal
- Example: 99999999.99 (maximum value)

### 4. AUTO_INCREMENT

Automatically generates sequential numbers:

```sql
id INT AUTO_INCREMENT PRIMARY KEY
```

**How it works:**
1. First insert: id = 1
2. Second insert: id = 2
3. Third insert: id = 3
4. Delete id=2, next insert: id = 4 (not 2!)

**Benefits:**
- No need to specify ID when inserting
- Guaranteed unique
- No conflicts when multiple users insert

### 5. TIMESTAMP Fields

```sql
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

**created_at:**
- Automatically set when row is inserted
- Never changes after creation
- Tracks when employee was added

**updated_at:**
- Automatically set on insert
- Updates automatically when row is modified
- Tracks last modification time

### 6. Database Connection Pattern

**Bad practice - No connection management:**
```python
connection = mysql.connector.connect(...)
cursor = connection.cursor()
cursor.execute("SELECT * FROM employees")
# If error occurs here, connection never closes! Memory leak!
```

**Good practice - Proper cleanup:**
```python
connection = None
try:
    connection = mysql.connector.connect(...)
    cursor = connection.cursor()
    cursor.execute("SELECT * FROM employees")
    # Do work
except Error as e:
    print(f"Error: {e}")
finally:
    if connection and connection.is_connected():
        cursor.close()
        connection.close()  # Always closes, even if error occurs
```

### Step 3: Understanding database.py

Let's break down the key functions:

#### Function: get_db_connection()

```python
def get_db_connection():
    try:
        connection = mysql.connector.connect(**DB_CONFIG)
        if connection.is_connected():
            return connection
    except Error as e:
        print(f"Error: {e}")
        return None
```

**What it does:**
- Creates connection to MySQL
- Returns connection object if successful
- Returns None if failed
- Prints error message for debugging

**Usage pattern:**
```python
connection = get_db_connection()
if connection:
    # Connection successful, do work
    cursor = connection.cursor()
    # ...
else:
    # Connection failed, handle error
    return {"error": "Database unavailable"}
```

#### Function: create_database()

```python
def create_database():
    connection = mysql.connector.connect(
        host=DB_CONFIG["host"],
        user=DB_CONFIG["user"],
        password=DB_CONFIG["password"],
        port=DB_CONFIG["port"]
        # Notice: no database parameter!
    )
    cursor = connection.cursor()
    cursor.execute("CREATE DATABASE IF NOT EXISTS employee_db")
```

**What it does:**
- Connects to MySQL server (not a specific database)
- Creates the `employee_db` database
- `IF NOT EXISTS` prevents error if already exists

#### Function: create_employees_table()

```python
create_table_query = """
CREATE TABLE IF NOT EXISTS employees (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    department VARCHAR(50) NOT NULL,
    salary DECIMAL(10, 2) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
)
"""
```

**Breaking down the table structure:**

**id INT AUTO_INCREMENT PRIMARY KEY**
- `INT` - Integer type
- `AUTO_INCREMENT` - Database assigns 1, 2, 3, ...
- `PRIMARY KEY` - Unique identifier for each row

**name VARCHAR(100) NOT NULL**
- `VARCHAR(100)` - Text up to 100 characters
- `NOT NULL` - Must provide a value (required field)

**email VARCHAR(100) NOT NULL UNIQUE**
- `NOT NULL` - Required
- `UNIQUE` - No two employees can have same email

**department VARCHAR(50) NOT NULL**
- Department name, required

**salary DECIMAL(10, 2) NOT NULL**
- `DECIMAL(10, 2)` - Total 10 digits, 2 after decimal point
- Can store up to: 99,999,999.99
- Exact precision (no rounding errors)

**created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP**
- Automatically set to current date/time on insert
- Never changes after creation

**updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP**
- Set on insert
- Automatically updates whenever row is modified

## 🎓 Interview Questions with Answers

### Question 1: What is a primary key and why is it important?

**Answer:**
A primary key is a column (or combination of columns) that uniquely identifies each row in a table.

**Characteristics:**
- **Unique**: No two rows can have the same primary key value
- **Not NULL**: Must always have a value
- **Immutable**: Should never change once set
- **One per table**: Only one primary key per table (but can be composite)

**Why it's important:**
1. **Uniqueness**: Guarantees each record is unique
2. **Relationships**: Used to link tables together (foreign keys)
3. **Performance**: Database automatically indexes primary keys for fast lookups
4. **Data integrity**: Prevents duplicate or orphaned records

**Example:**
```sql
CREATE TABLE employees (
    id INT AUTO_INCREMENT PRIMARY KEY,  -- Primary key
    email VARCHAR(100) UNIQUE           -- Not a primary key, but unique
);
```

**Employee ID as primary key:**
- Employee 1: John Doe
- Employee 2: Jane Smith
- Even if both work in same department, they have unique IDs

### Question 2: What's the difference between VARCHAR and TEXT data types?

**Answer:**

| Aspect | VARCHAR | TEXT |
|--------|---------|------|
| **Length** | Fixed max length (e.g., VARCHAR(100)) | Up to 65,535 characters |
| **Storage** | Length prefix + data | Length prefix + data |
| **Indexing** | Can be fully indexed | Requires prefix length |
| **Performance** | Faster for short text | Slower for operations |
| **Use case** | Names, emails, titles | Long descriptions, articles |

**When to use VARCHAR:**
- Fixed or limited length data
- Names (VARCHAR(100))
- Emails (VARCHAR(100))
- Departments (VARCHAR(50))
- Need to index the full column

**When to use TEXT:**
- Long, variable content
- Employee descriptions
- Comments
- Articles or blog posts
- Don't know exact length needed

**Example:**
```sql
CREATE TABLE employees (
    name VARCHAR(100) NOT NULL,      -- Short, known max length
    bio TEXT,                        -- Long, unpredictable length
    email VARCHAR(100) UNIQUE        -- Short, need to index
);
```

### Question 3: Why use DECIMAL instead of FLOAT for money?

**Answer:**
DECIMAL provides exact precision, while FLOAT has rounding errors due to binary representation.

**Problem with FLOAT:**
```python
# Python example showing float precision issue
price1 = 0.1
price2 = 0.2
total = price1 + price2
print(total)  # Output: 0.30000000000000004 (NOT 0.3!)
```

**Why this happens:**
- Computers store numbers in binary
- Some decimal numbers cannot be represented exactly in binary
- Causes small rounding errors
- Errors accumulate over many calculations

**DECIMAL advantages:**
- Stores numbers as exact decimal values
- No rounding errors
- Perfect for financial calculations

**DECIMAL(10, 2) explanation:**
- `10` = Total digits
- `2` = Digits after decimal point
- Can store: -99,999,999.99 to 99,999,999.99

**Example:**
```sql
CREATE TABLE products (
    price DECIMAL(10, 2) NOT NULL,    -- Exact: 19.99
    weight FLOAT,                     -- Approximate: 1.234kg (precision not critical)
    rating FLOAT                      -- Approximate: 4.5 stars
);
```

**Use DECIMAL for:**
- Money (salary, prices, balances)
- Percentages in financial calculations
- Anything requiring exact precision

**Use FLOAT for:**
- Scientific measurements
- Statistics
- Cases where approximate values are acceptable

### Question 4: What is the purpose of try-except-finally in database operations?

**Answer:**
The try-except-finally pattern ensures proper resource cleanup even when errors occur.

**Structure:**
```python
try:
    # Code that might fail
    connection = get_db_connection()
    cursor = connection.cursor()
    cursor.execute("SELECT * FROM employees")
except Error as e:
    # Handle errors
    print(f"Error: {e}")
finally:
    # Always runs, even if error occurs
    if connection and connection.is_connected():
        cursor.close()
        connection.close()
```

**Why each part:**

**try block:**
- Contains code that might raise an exception
- Database operations can fail (network, permissions, SQL errors)

**except block:**
- Catches specific errors
- Prevents program crash
- Allows graceful error handling
- Logs errors for debugging

**finally block:**
- **Always executes**, whether error occurred or not
- Ensures database connections are closed
- Prevents resource leaks
- Frees up database connection pool

**Without finally - BAD:**
```python
connection = get_db_connection()
cursor = connection.cursor()
cursor.execute("INVALID SQL")  # Error occurs here
connection.close()  # NEVER RUNS! Connection leak!
```

**With finally - GOOD:**
```python
try:
    connection = get_db_connection()
    cursor = connection.cursor()
    cursor.execute("INVALID SQL")  # Error occurs
except Error as e:
    print(f"Error: {e}")
finally:
    if connection:
        connection.close()  # ALWAYS RUNS! Clean up guaranteed!
```

### Question 5: What does `CREATE TABLE IF NOT EXISTS` do?

**Answer:**
The `IF NOT EXISTS` clause prevents an error if the table already exists.

**Without IF NOT EXISTS:**
```sql
CREATE TABLE employees (...);
-- Run again: ERROR: Table 'employees' already exists
```

**With IF NOT EXISTS:**
```sql
CREATE TABLE IF NOT EXISTS employees (...);
-- Run again: No error, table unchanged
```

**Behavior:**
- If table exists: Do nothing, no error
- If table doesn't exist: Create it

**Why it's useful:**
1. **Idempotent scripts**: Can run multiple times safely
2. **Initialization**: Setup scripts won't fail on rerun
3. **Development**: Restart application without manual cleanup
4. **Deployment**: Safe to run on both new and existing databases

**Similar patterns:**
```sql
-- Database
CREATE DATABASE IF NOT EXISTS employee_db;

-- Drop safely
DROP TABLE IF EXISTS old_table;

-- Alter table
ALTER TABLE employees ADD COLUMN IF NOT EXISTS phone VARCHAR(20);
```

**When NOT to use:**
- When you want to know if table exists (for logic)
- When you need to error if table missing
- When recreating table with new structure (use DROP first)

### Task 2: Insert Sample Employee Data

**Instructions:**
Write a function to insert a sample employee into the database.

**Solution:**

```python
def insert_sample_employee():
    """
    Inserts a sample employee into the database
    """
    connection = get_db_connection()

    if connection:
        try:
            cursor = connection.cursor()

            # SQL INSERT query
            insert_query = """
            INSERT INTO employees (name, email, department, salary)
            VALUES (%s, %s, %s, %s)
            """

            # Sample employee data
            employee_data = (
                "Alice Johnson",
                "alice.johnson@company.com",
                "HR",
                55000.00
            )

            # Execute the insert
            cursor.execute(insert_query, employee_data)

            # Commit the transaction (save changes)
            connection.commit()

            print(f"✅ Employee added with ID: {cursor.lastrowid}")

            cursor.close()

        except Error as e:
            print(f"❌ Error inserting employee: {e}")

        finally:
            if connection.is_connected():
                connection.close()

# Test it
insert_sample_employee()
```

**Understanding the code:**

**%s placeholders:**
- Prevents SQL injection
- Values are safely escaped
- Don't use f-strings for SQL queries!

**connection.commit():**
- Saves changes to database
- Without commit, changes are rolled back
- Required for INSERT, UPDATE, DELETE

**cursor.lastrowid:**
- Returns the auto-generated ID
- Useful to know which ID was assigned

**Why use tuples:**
```python
employee_data = ("Alice", "alice@company.com", "HR", 55000.00)
cursor.execute(insert_query, employee_data)
```
- Values are safely parameterized
- Prevents SQL injection attacks
